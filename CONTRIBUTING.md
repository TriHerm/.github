# Contributing to TriHerm Open Source

Thanks for contributing to projects published by TriHerm and TriHerm Labs.

## Before you start

- Read the repository README, license, and any project-specific contribution notes.
- Search existing issues and pull requests before opening a duplicate.
- Keep changes focused, reviewable, and scoped to the problem being solved.
- Do not include proprietary source code, private data, credentials, or third-party assets without clear redistribution rights.

## Pull requests

A good pull request should:

1. Explain the problem and the intended outcome.
2. Keep unrelated refactors out of the change.
3. Include tests or verification steps when behavior changes.
4. Preserve backwards compatibility unless the change explicitly requires otherwise.
5. Update documentation when public behavior or setup changes.

Project-specific instructions take precedence over this organization-wide default.
